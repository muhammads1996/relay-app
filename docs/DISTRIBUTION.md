# Distributing Relay

## Building release binaries

The repository builds `relay` for CLI usage and `relay-app` for the native desktop workbench. The GitHub CI workflow validates formatting, modules, vetting, tests, and Windows release builds. Packaging, signing, and publishing remain deliberate release-owner steps.

The Windows desktop app also has repeatable MSI packaging. The MSI installs
per-user under `%LOCALAPPDATA%\Programs\Relay`, creates a Start Menu shortcut,
supports major upgrades, and leaves the user's workspace database intact on
uninstall.

Before producing a release artifact:

1. Start from a clean worktree and confirm the intended version in `cmd/relay/main.go` and the macOS package `VERSION`.
2. Run `gofmt -w` on changed Go files, then run `git diff --check`, `go mod verify`, `go vet ./...`, and `go test ./...`.
3. Build on the target OS with `-trimpath` and release linker flags.
4. Smoke-test `relay version`, a CLI collection run, and the desktop workbench.
5. Generate SHA-256 checksums, sign platform artifacts, and verify signatures before publishing.

Local Windows builds:

```sh
# Windows (cross-compiles from any OS - the Windows webview path is pure Go)
GOOS=windows GOARCH=amd64 go build -trimpath -ldflags "-s -w" -o relay.exe ./cmd/relay
GOOS=windows GOARCH=amd64 go build -trimpath -tags desktop,production \
  -ldflags "-s -w -H windowsgui" -o relay-app.exe ./cmd/relay-app
```

Build and validate the Windows desktop MSI from Windows:

```powershell
pwsh -File scripts/build-windows-msi.ps1
```

The script restores the repository-pinned WiX tool, builds the desktop app,
creates an embedded-cab MSI, validates its payload with a Windows Installer
administrative extraction, and writes:

```text
dist/Relay-<version>-windows-x64.msi
dist/Relay-windows-x64.msi
dist/SHA256SUMS-windows.txt
```

Tagged builds can publish those files through
`.github/workflows/release-windows.yml`. Because the workflow keeps beta builds
as GitHub prereleases, use an explicit version tag in the marketing download
URL:

```text
https://github.com/muhaymien96/relay/releases/download/v0.3.0/Relay-windows-x64.msi
```

The MSI contains `relay-app.exe` only. Keep `relay.exe` as a separate portable
artifact for terminals and CI. See `installer/windows/README.md` for signing,
tooling terms, and installer behavior.

Local builds for the current OS:

```sh
go build -trimpath -ldflags "-s -w" -o relay ./cmd/relay
go build -trimpath -tags desktop,production -ldflags "-s -w" -o relay-app ./cmd/relay-app
```

For a shareable macOS GUI build, produce a zipped `.app` bundle on macOS:

```sh
bash scripts/package-macos-app.sh
```

The script builds `cmd/relay-app`, creates `dist/Relay.app`, self-signs it
ad hoc, and writes `dist/Relay-macos-universal.zip`. Set `ARCHES=arm64` or
`ARCHES=amd64` to build only one Mac architecture. Wails/WKWebView macOS GUI
builds require the macOS toolchain; Windows/Linux can cross-compile the CLI
but cannot produce a proper no-terminal macOS `.app` bundle.

Linux desktop builds may need a WebKitGTK build tag depending on installed distro packages:

```sh
go build -trimpath -tags desktop,production,webkit2_41 -ldflags "-s -w" -o relay-app ./cmd/relay-app
```

The `.syso` files in `cmd/relay*/` embed the icon, version info, and an
application manifest (per-monitor DPI, long paths) into Windows builds
automatically. Regenerate them after changing `winres/winres.json`:

```sh
go run github.com/tc-hib/go-winres@v0.3.3 make --in cmd/relay-app/winres/winres.json --out cmd/relay-app/rsrc
go run github.com/tc-hib/go-winres@v0.3.3 make --in cmd/relay/winres/winres.json --out cmd/relay/rsrc
```

## "Windows protected your PC" (SmartScreen)

When colleagues download and run an unsigned `relay-app.exe`, Microsoft
Defender SmartScreen shows **"Windows protected your PC"**. This is not a
defect in the binary — SmartScreen flags any executable that (a) carries the
internet "Mark of the Web" and (b) has no code signature or download
reputation yet.

**Immediate workarounds** (tell your colleagues one of these):

1. In the SmartScreen dialog click **More info → Run anyway**.
2. Or before launching: right-click the `.exe` → **Properties** → tick
   **Unblock** → OK.
3. Or in PowerShell: `Unblock-File .\relay-app.exe`.
4. Verify what you're unblocking first: compare the file's SHA-256
  (`Get-FileHash .\relay-app.exe`) against a checksum generated by the
  person or pipeline that built it.

Distribution inside a zip does not avoid this: Windows propagates the
Mark of the Web to extracted files. Sharing over an internal file share or
deploying via Intune/SCCM does avoid it (no MotW).

**The permanent fix is Authenticode code signing.** This requires a
certificate that identifies you or your company — it can't be generated;
options in rough order of practicality:

| Option | Cost | SmartScreen effect |
|---|---|---|
| **Azure Trusted Signing** | ~$10/month | Microsoft-issued identity; reputation accumulates quickly |
| **EV code-signing certificate** (DigiCert, Sectigo, …) | ~$300–500/yr | Immediate SmartScreen reputation |
| **OV code-signing certificate** | ~$80–200/yr | Signed + publisher named; reputation builds with downloads |
| Unsigned | free | Warning until enough users have run that exact binary |

When release automation is added, sign Windows binaries with Authenticode and timestamp them as part of the pipeline. Without signing, SmartScreen warnings are expected for downloaded executables.

macOS has the analogous gate (Gatekeeper): unsigned apps need right-click →
Open the first time, and the real fix is an Apple Developer ID certificate
plus notarization.

## What colleagues get

- `relay-app.exe` — the desktop workbench. First launch creates
  `%APPDATA%\Relay\relay.db` as the workspace; no installer, no admin
  rights, no runtime dependencies (WebView2 ships with Windows 10/11).
- `Relay-windows-x64.msi` — the per-user Windows desktop installer. It adds a
  Start Menu shortcut and can be removed from Windows installed-apps settings.
  Uninstalling it preserves the workspace database.
- `Relay-macos-universal.zip` — the macOS desktop workbench. It contains
  `Relay.app`; first launch creates `~/Library/Application Support/Relay/relay.db`.
- `relay.exe` — the CLI for terminals and CI (`relay run`, import/export).
- Delete the app or binary to uninstall; each user's workspace database stays
  in their OS app-data folder unless they remove it separately.
