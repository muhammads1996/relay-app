# Relay UI and release-readiness review

Date: 30 September 2026. Scope: current worktree, the [original UX audit](UX_AUDIT_2026-09-28.md), shared browser/desktop UI, implementation evidence, and a fresh Windows desktop candidate. No release tag, installer publication, production workspace migration, or competitor comparison was performed.

## Decision

**Suitable for local beta evaluation, not a finalized production release or complete Postman replacement.** The review corrected confirmed UI defects and built a fresh desktop candidate. Several original acceptance criteria remain unimplemented or unverified. All F01-F24 items are accounted for below; they are not all resolved.

The strongest supported workflow is local HTTP request authoring, assertions and scripts, collection execution, and export to CI artifacts. The premium UX goal is a product target, not an established usability or comparative-performance result.

## Remaining findings

1. **High: daily-use authentication and download workflows are incomplete.** The editor supports bearer, basic, and API-key auth, but does not integrate the OAuth manager. Full-response streaming exists in the engine but not in the UI. Custom CA and mTLS implementations do not establish an accessible desktop configuration flow. Owners: request editor, engine integration, desktop shell. Close with local OAuth/refresh/certificate fixtures and a complete 100 MiB UI download.
2. **High: file continuity is incomplete for Test Management and legacy workspaces.** Schema-v2 request/environment saves update files, while test definitions remain in SQLite; unmarked legacy workbench edits still diverge from CLI files. Owners: workspace/storage and Test Management. Close with explicit migration, recovery, and UI-to-CLI parity tests for every promised definition type.
3. **High: native release acceptance is incomplete.** A newly compiled Windows desktop binary opened a responsive native window on this host. Native clipboard, downloads, file dialogs, unsaved-close recovery, 125/150/200% OS scaling, installer upgrades, backup/restore, and sleep/resume were not verified. A temporary WebView2 debugging session did not expose its requested inspection port and was closed. Browser automation is not evidence for these native interactions.
4. **Medium: migration, history, and recovery still have functional gaps.** Advanced Postman behavior, OpenAPI YAML and environment migration need acceptance coverage; exact immutable history replay is unavailable. File-level recoverable operations do not supply a complete user-facing trash/undo flow. Owners: importer, history, workspace UI.
5. **Medium: accessibility and competitive UX are not certified.** This pass improves labels, masked inputs, keyboard-operated disclosures, responsive controls, and regression coverage. It does not establish full keyboard completion, contrast compliance for every component, screen-reader behavior, or superiority over competitors. Full workflow observation with five representative users remains required.

## Changes made in this review

- Prevented delayed History and Settings loads from replacing another active view; superseded loads cannot render an older screen.
- Added individual-request cancellation and elapsed time. Browser cancellation propagates to the Go request context and closes the local upstream fixture. It cannot undo server-side work that already occurred. Cancellation remains accessible after changing request-editor tabs.
- Masked bearer tokens, passwords, and API-key values by default, with explicit reveal controls and programmatic labels. Removed the misleading implication that masking protects literal credentials at rest.
- Kept method, URL, and Send on one row at supported desktop widths. Corrected populated response-pane clipping at 760x480 with an explicit scroll boundary.
- Corrected persisted Basic/Full mode display: select values must be assigned after their options exist.
- Collapsed secondary Test Management identity/request/traceability configuration, retained per-test expansion during rerenders, and removed unconfigured Xray actions from the selected-test surface. Assertions and the last result remain the primary content.
- Updated the README and client guide to describe supported capabilities, workspace formats, secret handling, and limitations accurately.
- Repaired the stale browser audit selectors, required a successful local response, added minimum-size coverage and failure-injection regressions, and moved disposable workspace setup outside Playwright's cleaned output directory.
